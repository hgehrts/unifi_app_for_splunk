# UniFi App for Splunk — v1.1.0 plan

**Status:** APPROVED — building. Decisions locked 2026-06-18.
**Target version:** 1.1.0 (companion app `unifi_app_for_splunk`).
**Research:** live against production `splk` (Splunk 10.4) + the controller data.

This release adds manual multi-select entity pickers, a real Setup page that
writes the index macros, dashboard auto-refresh, much richer syslog field
extraction + filtering + clustering, device hardware telemetry (incl. fan/temp
from syslog) and software version, and a new Auditing dashboard.

---

## 0. What the data supports (evidence)

Confirmed on the live system before designing:

| Capability | Source | Notes |
|------------|--------|-------|
| Software version per device | API `unifi:device:detail` | `firmwareVersion`, `firmwareUpdatable`, `version` ✅ |
| CPU / mem / load / uptime / uplink rates | API `unifi:device:stats` | already collected ✅ |
| Port/PoE/radio detail | API `unifi:device:detail` | `interfaces.ports{}.poe.*`, `speedMbps`, radio channel/width ✅ |
| **Fan speed / RPM / PSU temperature** | **syslog `ubnt-fanctrl`** | e.g. `Fan speed 25% | pwm 64 | fan rpm 2311 | sensor PSU temp 42°C`. **Only switches** emit it; **not in the API at all.** |
| Severity / facility | SC4S fields | `sc4s_syslog_severity` (info/notice/warning/err…), `sc4s_syslog_facility` ✅ |
| Port link up/down | syslog `kernel` | `Port 3 link up` / `Port 3 link down` ✅ |
| Device SSH logins (who/where/when) | syslog `dropbear` | `Password auth succeeded for 'admin' from 192.168.1.1:41602` ✅ |
| Config-change detection | API snapshots (~180 s) | diff successive inventory snapshots ✅ |
| **Controller-UI admin logins / config audit** | — | **NOT available** in this syslog stream or the Integration API. Documented; optional future via forwarding the controller audit log. |

## 1. Multi-select entity pickers on the drilldowns

- Device Drilldown: `input.multiselect` token **`device`** populated from
  `unifi_device_lookup` (label `device_name`). Searches change from
  `device_name="$device$"` to `device_name IN ($device$)`.
- Client Drilldown: `input.multiselect` token **`client`** populated from
  `unifi_client_lookup` (label `name (mac)`, value `client_mac`). Searches use
  `client_mac IN ($client$)`.
- **Default = ALL** when opened directly; a drilldown link pre-selects just the
  clicked entity (single value in the multiselect); user can add more.
- Token delimiter configured so multiselect emits a valid `IN (...)` list
  (quoted values via the multiselect `delimiter`/`prefix`/`suffix` or a
  `valuePrefix/valueSuffix`).

## 2. Setup page (HTML) that discovers indexes and writes the macros

- A proper app **Setup page** (`default/setup.xml` → `setup` view + a small
  JS/HTML form, or a Studio "Index Finder" page plus a setup endpoint).
  Chosen approach: an **HTML setup dashboard** with:
  - an SPL panel the admin can run to discover candidate indexes, e.g.
    `| eventcount summarize=false index=* | search index!=_* | ...` and
    `| metasearch index=* sourcetype=ubnt* | stats count by index` to find the
    syslog index, and `… sourcetype=unifi:device | stats count by index` for the
    TA index;
  - two inputs (TA index expr, syslog index expr) prefilled with current macro
    values;
  - a **Submit** button that POSTs to the Splunk REST API
    (`/servicesNS/nobody/unifi_app_for_splunk/configs/conf-macros/<name>`) to
    update `unifi_index` and `unifi_syslog_index` definitions, then sets
    `app/is_configured=1`.
- Registered via `app.conf [install] is_configured` + `[ui]` and an
  `appserver/static` JS helper.

## 3. Dashboard auto-refresh

- Add a **refresh interval input** (dropdown: Off / 30s / 1m / 5m / 15m) on each
  dashboard, wired to each data source's `refresh`/`refreshType` so users control
  it. **Default = Off** (manual) to avoid constant background searches.

## 4. Richer syslog: extractions + filters + clustering (Device Drilldown + app-wide)

New search-time extractions (props/transforms), added app-wide on `ubnt*`:

- `severity` ← `sc4s_syslog_severity` (alias) + numeric `severity_rank` for
  sorting/threshold.
- `link_state` (`up`/`down`) and `port` from `kernel` "Port N link up/down".
- `poe_event` / `poe_port` from PoE messages.
- `event_action` normalization: `up`, `down`, `connect`, `disconnect`, `kick`,
  `roam`, `auth_fail`, `dns`, `fan`, `login`, `config`.
- fan fields (see §5).

Device Drilldown syslog section gets:
- **Filters** (inputs): severity (multiselect), event_action/type (multiselect),
  proc (multiselect), free-text search.
- **Clustering panels**:
  - events **by client** (top talkers),
  - events **by device** (when multiple selected),
  - events **by message pattern** (using `cluster` / `punct` to group similar
    messages and show counts).
- The raw event table stays, but below the analytics, with the new fields as
  columns (severity, event_action, port, client).

## 5. Device hardware telemetry + software version (Device Drilldown)

- **Software version** panel: `firmwareVersion`, `firmwareUpdatable`, `model`,
  `adoptedAt`, uptime — from `unifi:device:detail` / `stats`.
- **Fan & temperature** panel (syslog-derived): extract
  `fan_speed_pct`, `fan_pwm_set`, `fan_pwm_actual`, `fan_rpm`, `psu_temp_c`
  from `ubnt-fanctrl`; timechart temp + fan%/RPM. Only populated for devices
  that emit it (switches); a note covers APs/gateway.
- **Uplink throughput** (rx/tx Bps → Mbps) and **load averages** trends from
  `unifi:device:stats`.
- **Ports/PoE** table from `unifi:device:detail` (`interfaces.ports{}` — port,
  state, speed, PoE state/type).

## 6. Auditing dashboard (new view `unifi_audit`)

Built from available data (decision: build + document the controller-audit gap):
- **Device logins** (from `dropbear`): table + timechart of `user`,
  `src_ip` (from where), `device_name` (which device), success/fail, with
  drilldown to Device Drilldown.
- **Port up/down history** (from `kernel`): per device/port state changes.
- **Config-change detection** (from API snapshots): detect when a device's
  `firmwareVersion`, `name`, `ipAddress`, or a network's key fields change
  between snapshots (`streamstats current=f` compare), show "what changed when".
- **Severity heatmap** (warnings/errors over time by device).
- A prominent **note** + a docs section: full controller-UI admin/config audit
  requires forwarding the UniFi controller's own audit log to Splunk (out of
  scope of the Integration API). Docs will show where that lives.

## 7. Build order

1. Extractions first (transforms/props): severity, link/port, poe, fan/temp,
   event_action — validate each against live data.
2. Multi-select inputs on Device + Client drilldowns (+ refresh control).
3. Device Drilldown rebuild: version + hardware + fan/temp + richer syslog
   (filters + clustering).
4. New Auditing dashboard.
5. Setup page (HTML + macro write-back).
6. Validate live on `splk`, screenshot, bump to 1.1.0, docs, commit/push.

## 8. Decisions (locked)

| Q | Decision |
|---|----------|
| Audit scope | Build from available (SSH logins + up/down + config drift) **and** add docs on forwarding the controller audit log later. |
| Fan/temp | Extract from syslog (`ubnt-fanctrl`); only switches populate it. |
| Refresh | Control exposed on dashboards; **default Off**. |
| Setup page | Real HTML setup page that runs discovery SPL and **writes** the macros on Submit. |
| Multi-select default | **ALL** when opened directly; drilldown pre-selects the clicked entity; user can add more. |
